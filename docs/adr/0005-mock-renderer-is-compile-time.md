# Mock Renderer is compile-time Analyzer machinery, not Alloy runtime

Four entangled files — `src/pebble-output.ts` (1481 LOC), `src/pebble-render.ts` (357 LOC), `src/pebble-dom-shim.ts` (266 LOC), `src/pebble-reconciler.ts` (54 LOC) — advertise themselves as the Alloy runtime: `PocoRenderer` class, `render()` entry point, `typeof screen !== 'undefined'` real-Poco branch, watch-button/touch event wiring, Preact reconciler bridge, public re-exports from `src/index.ts`. They are not. Their only production caller is `scripts/analyze.ts:712`, which invokes the example's `main()` to drive a perturbation render against `MockPoco` and harvest the draw log for IR assembly. Emitted Target output (piu scene graph, Rocky.js canvas, C SDK) never references `render()` or `PocoRenderer`; Pebble Alloy's ~3 KB runtime heap cannot host Preact on-watch in the first place. As of 2026-05-23 we relocate these four files into `scripts/analyzer/mock/` (one file each, preserved as `poco.ts`, `render.ts`, `dom-shim.ts`, `reconciler.ts`), delete the dead runtime branches, extract the shared spec data (`COLOR_PALETTE`, `FONT_PALETTE`, resolvers) into `src/palette.ts`, strip the misleading public API surface, and migrate examples from `export function main() { return render(<X/>); }` to `export default function X()` so the Analyzer owns the `render()` wrap. `src/pebble-dom.ts` stays in `src/` — components produce its shape and the public entry re-exports its types.

## Why

- **Locality.** The Mock Renderer's only consumer is the Analyzer; living in `src/` next to user-facing hooks and components scattered its true role across two layers. Folding into `scripts/analyzer/` puts it with the rest of the compile-time pipeline.
- **Mental-model alignment.** New contributors reading `src/pebble-output.ts` see "Alloy runtime" and infer an on-watch execution path that does not exist. Per-Adapter Targets become harder to understand when a phantom fourth runtime appears to compete with them.
- **Public API shrinks to what consumers actually use.** `render`, `PocoRenderer`, `COLOR_PALETTE`, `FONT_PALETTE`, `colorFromHex`, `colorDistance`, `nearestColorName`, `legibleOver`, `registerFont`, `lookupFontSpec`, `getTextWidth`, `resolveColorName`, `resolveFontName`, and types `RGB` / `FontSpec` / `PocoRenderOptions` are removed from `src/index.ts`. No test, Target, plugin, or example imports them from the public entry; the README references `render` only in illustrative boilerplate that the Analyzer now produces.
- **Palette as shared spec.** `COLOR_PALETTE` and `FONT_PALETTE` are read by three callers — the Analyzer (name → hex on IR fields), the Mock Renderer (Poco color/font construction), the `getTextContentSize` hook (text-metric layout). Splitting them into `src/palette.ts` lets the hook keep its `src/hooks/` home (a Vite-bundle constraint — `src/` cannot import from `scripts/`) while the Mock Renderer reads the same spec from its new home in `scripts/analyzer/`.
- **Examples become pure components.** `export default function X()` removes the `render()` boilerplate from every example and makes the Analyzer the single owner of the perturbation-render entry. The dual-fallback `exampleMod.main ?? exampleMod.default` in `scripts/analyze.ts:712-713` collapses to `exampleMod.default`.

## Rejected alternatives

- **Keep `pebble-output.ts` in `src/` as documented runtime.** Status quo. Continues advertising an on-watch path that no production caller uses. Future contributors keep inferring the wrong architecture. Rejected — Locality is load-bearing here.
- **Consolidate all four files into one `scripts/analyzer/mock-renderer.ts`.** ~2000 LOC after dead-code removal. Destroys git history at the moment of relocation, forces manual reconciliation of four discrete concerns (Poco draw helpers, render entry, DOM shim, Preact bridge) into one edit, and violates the "don't restructure during relocation" principle. Rejected — relocate as four cohesive files; further consolidation is a separate decision if it ever pays.
- **Split `pebble-output.ts` into themed subfiles during the relocation** (`scripts/analyzer/mock/{renderer,draw,shim}.ts`). Premature additional internal Seam beyond the four existing files. Rejected — keep current file boundaries; split later if internal cohesion stops paying.
- **Keep `render` as a public no-op marker so example boilerplate stays familiar.** Ships dead-ish symbol forever; users still think it does something at runtime. Rejected — the clean break is cheaper than perpetual confusion.
- **Preserve the real-Poco branch and watch-event wiring as an escape hatch for a future Preact-on-watch host.** No such host is planned; the 3 KB heap constraint argues against it ever existing. Git history preserves the code if it ever becomes viable. Rejected — dead code masquerading as live code is worse than no code.
- **Leave the palette inside the relocated Mock Renderer file.** The `getTextContentSize` hook in `src/hooks/` needs it, and `src/` cannot cleanly import from `scripts/` through the Vite library bundle. Rejected for the Vite constraint; the split also gives a future Target direct read access to canonical color/font names without dragging the renderer along.

## Consequence

- `src/pebble-output.ts`, `src/pebble-render.ts`, `src/pebble-dom-shim.ts`, `src/pebble-reconciler.ts` deleted; their contents move (preserving git history) to `scripts/analyzer/mock/{poco,render,dom-shim,reconciler}.ts` with dead runtime code removed in-place.
- New `src/palette.ts` holds `COLOR_PALETTE`, `FONT_PALETTE`, `lookupFontSpec`, `colorFromHex`, and related math (~100 LOC). Not re-exported from `src/index.ts`. Three importers reach it directly: `scripts/analyze.ts`, `scripts/analyzer/mock-renderer.ts`, `src/hooks/getTextContentSize.ts`.
- `src/index.ts` loses 13 named exports plus 3 type re-exports tied to the former runtime façade.
- ~100 example files convert from `export function main() { return render(<X/>); }` to `export default function X()`. The `import { render } from '../src/index.js'` line and the `import type Poco from 'commodetto/Poco'` line both drop.
- `scripts/analyze.ts:712-713` simplifies to `const exampleComponent = exampleMod.default; const exampleMain = () => render(<exampleComponent />);` with `render` now imported from the relocated `scripts/analyzer/mock-renderer.ts`.
- `src/hooks/getTextContentSize.ts:9` import path swaps from `../pebble-output.js` to `../palette.js`.
- Real-Poco branch in `pebble-render.ts:151-162`, `wireWatchButtons` (L182-213), and `wireWatchTouch` (L219-244) deleted with no replacement.
- `package.json` version bumps `0.9.0` → `0.10.0` for the breaking public API removal.
- README's example block updates to drop the `import { render }` line and the `main()` wrapper.
- CONTEXT.md gains **Mock Renderer** and **Palette** glossary entries plus two Relationship lines (already added at decision time).
- ADR 0001's Adapter-Locality argument (Adapters live in `scripts/` because `src/compiler/index.ts` is a Vite library entry that would otherwise bundle the entire emitter tree) extends naturally: the Mock Renderer joins the Adapters in `scripts/` for the same reason inverted — its only consumer is `scripts/analyze.ts`, and bundling it into `dist/lib` shipped Alloy-runtime-shaped dead code to every consumer.
